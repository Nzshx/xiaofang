# 移动端前端接口字段对照说明

> 文档日期：2026-08-10  
> 对应后端：`main.py`  
> 对应测试前端：`mobile-problem-detail-demo.html`

## 1. 文档目的

本文说明移动端“问题详情”页面使用的两个接口，以及每个返回字段在前端页面中的对应位置和具体作用。

两个接口分别为：

```http
GET /analyze/fire-safety/{job_id}/mobile-view
GET /analyze/fire-safety/{job_id}/mobile-view/hazards/{hazard_id}
```

- `mobile-view`：初始化整个问题详情页面，包括图片、二级问题分类推荐、三级问题候选和默认三级问题详情。
- `mobile-view/hazards/{hazard_id}`：用户切换某个三级问题后，加载该三级问题独立的描述、法规和整改建议。

## 2. 页面区域与数据来源概览

| 前端区域 | 主要数据来源 |
|---|---|
| 顶部现场图片 | `image_url` |
| “问题分类”标题 | `mobile_view.field_labels.category` |
| 上方问题分类框 | `default_category2_id`、`ai_recommended_categories[].label` |
| AI 推荐的问题分类标签 | `ai_recommended_categories[]` |
| 三级问题下拉列表 | `issue_options[]` |
| 问题描述 | `selected_hazard.description` |
| 关联条文法规 | `selected_hazard.regulations[]` |
| 默认前三条法规 | `selected_hazard.default_regulation_ids` |
| “添加”弹窗剩余法规 | `selected_hazard.remaining_regulation_ids` 或前端根据未展示法规计算 |
| 整改建议 | `selected_hazard.rectification_advice` |

# 3. 接口一：移动端页面初始化接口

## 3.1 请求

```http
GET /analyze/fire-safety/{job_id}/mobile-view
Authorization: Bearer <token>
```

## 3.2 顶层字段

| 字段 | 类型 | 对应前端位置 | 作用 |
|---|---|---|---|
| `job_id` | `string` | 不直接展示；保存在页面请求状态中 | 标识当前识别任务。后续请求三级问题详情时继续使用该任务 ID。 |
| `status` | `string` | 页面顶部接口状态提示条 | 判断任务是否可以展示。`done` 时渲染页面；`processing` 时显示处理中；`error` 时显示错误；`not_found` 时提示任务不存在。 |
| `image_key` | `string/null` | 当前不直接展示 | TOS 图片对象 Key，主要供后端和调试使用。前端预览应使用 `image_url`，不能自行拼接地址。 |
| `image_url` | `string/null` | 页面顶部现场图片预览区 | 短效签名图片 URL。存在时显示真实图片；为空或加载失败时显示图片占位图。 |
| `mobile_view` | `object/null` | 整个“问题详情”业务区域 | 移动端专用展示模型。任务未完成或失败时为 `null`。 |
| `error` | `string` | 页面顶部错误提示条 | 仅任务失败时返回，用于说明失败原因。 |

## 3.3 `mobile_view` 字段

| 字段 | 类型 | 对应前端位置 | 作用 |
|---|---|---|---|
| `field_labels` | `object` | 各业务字段标题 | 返回页面字段名称。目前使用 `field_labels.category` 将原“隐患类型”统一显示为“问题分类”。 |
| `category2_options` | `array` | 当前页面不完整展开；作为分类名称和完整值集备用 | 《问题分级》中的全部二级分类值集。当前测试页主要用作分类名称回退；后续如果增加人工修改分类下拉框，应直接使用该数组。 |
| `ai_recommended_categories` | `array` | “AI 推荐的问题分类”标签区域 | 本次识别出的所有二级分类，按置信度从高到低排列。点击某个标签时，上方问题分类框和下方详情会同步切换。 |
| `default_category2_id` | `string/null` | 上方“问题分类”框的初始选中值 | 指定首次进入页面时默认显示的二级分类，即置信度最高的二级分类。 |
| `default_hazard_id` | `string/null` | 默认三级问题选择状态 | 指定首次进入页面时默认展示的三级问题。问题描述、法规和整改建议都来自该三级问题。 |
| `issue_options` | `array` | 点击问题分类框右侧三角后展开的三级问题列表 | 本次识别出的全部三级问题，按二级分类分组展示。用户点击后请求三级问题详情接口。 |
| `selected_hazard` | `object/null` | 问题描述、法规、整改建议区域 | 默认三级问题的完整详情，页面首次加载时直接使用，避免再发一次详情请求。 |

## 3.4 `field_labels`

| 字段 | 类型 | 对应前端位置 | 作用 |
|---|---|---|---|
| `field_labels.category` | `string` | 问题分类卡片标题 | 当前固定为“问题分类”，用于替代旧名称“隐患类型”。 |

## 3.5 `category2_options[]`

| 字段 | 类型 | 对应前端位置 | 作用 |
|---|---|---|---|
| `category2_id` | `string` | 分类选项的内部值 | 前端选择分类时使用的稳定标识，例如 `category2:1.1.2`。该字段是接口临时生成的，不写入 MongoDB。 |
| `category2_code` | `string` | 当前不单独展示 | 《问题分级》中的二级分类编码，例如 `1.1.2`。可用于排序、搜索和表单提交。 |
| `label` | `string` | 分类选项显示文字 | 二级分类编码和名称组成的完整显示文本。 |

说明：

- `category2_options` 是《问题分级》的完整二级分类值集。
- `ai_recommended_categories` 只是本次图片实际识别出的二级分类。
- 两者不能混为一类：前者用于完整可选值，后者用于 AI 推荐。

## 3.6 `ai_recommended_categories[]`

| 字段 | 类型 | 对应前端位置 | 作用 |
|---|---|---|---|
| `category2_id` | `string` | 推荐标签的 `data-category-id`、页面当前选中分类状态 | 标识推荐标签属于哪个二级分类。点击标签后同步更新上方问题分类框。 |
| `category2_code` | `string` | 当前不单独展示 | 二级分类编码，可用于调试、排序或后续提交。 |
| `label` | `string` | AI 推荐标签文字；上方问题分类框文字 | 用户看到的二级分类名称。 |
| `confidence` | `number/null` | 当前不直接展示 | 原始置信度，范围 `0～1`。二级分类置信度取该分类下所有三级问题置信度的最高值。 |
| `confidence_percent` | `number/null` | AI 推荐标签右侧百分比 | 已转换为 `0～100` 的百分比，例如 `93` 显示为 `93%`。 |
| `issue_count` | `integer` | 当前测试页未单独展示 | 该二级分类下识别出的三级问题数量。后续可以显示为“2个问题”。 |
| `default_hazard_id` | `string` | 点击推荐分类后的默认三级问题 | 用户点击某个 AI 推荐分类时，前端用该值自动选择此分类下置信度最高的三级问题，并调用详情接口。 |

### 推荐分类点击逻辑

1. 用户点击某个推荐分类标签。
2. 前端将 `selectedCategoryId` 设置为该标签的 `category2_id`。
3. 上方问题分类框显示该标签的 `label`。
4. 前端读取该标签的 `default_hazard_id`。
5. 请求三级问题详情接口。
6. 更新问题描述、关联法规和整改建议。

## 3.7 `issue_options[]`

| 字段 | 类型 | 对应前端位置 | 作用 |
|---|---|---|---|
| `hazard_id` | `string` | 三级问题选项的内部值 | 当前任务内的临时三级问题 ID，例如 `h-0`。点击三级问题时作为详情接口路径参数。该字段不写入 MongoDB。 |
| `category2_id` | `string` | 三级问题分组及分类同步状态 | 表示该三级问题属于哪个二级分类。选择三级问题后，上方问题分类框同步切换到该分类。 |
| `category2` | `string` | 三级问题下拉列表的分组标题 | 用于按二级分类分组展示全部三级问题。 |
| `issue_id` | `string` | 三级问题选项副标题 | 《问题分级》中的正式三级问题编号。 |
| `category3` | `string` | 三级问题选项主标题 | 用户实际点击选择的三级问题名称。 |
| `confidence` | `number/null` | 当前不直接展示 | 三级问题原始置信度，范围 `0～1`。 |
| `confidence_percent` | `number/null` | 三级问题选项右侧百分比 | 三级问题置信度的百分比显示值。 |

## 3.8 `selected_hazard`

初始化接口中的 `selected_hazard` 与详情接口返回的 `selected_hazard` 结构相同，字段说明见第 4.4 节。

首次加载页面时：

- 上方问题分类框使用 `selected_hazard.category2`。
- 问题描述使用 `selected_hazard.description`。
- 法规使用 `selected_hazard.regulations`。
- 整改建议使用 `selected_hazard.rectification_advice`。

# 4. 接口二：三级问题详情接口

## 4.1 请求

```http
GET /analyze/fire-safety/{job_id}/mobile-view/hazards/{hazard_id}
Authorization: Bearer <token>
```

其中：

- `job_id` 来自当前任务。
- `hazard_id` 来自 `issue_options[].hazard_id` 或 `ai_recommended_categories[].default_hazard_id`。

## 4.2 调用时机

以下操作会调用详情接口：

1. 点击其他 AI 推荐的问题分类。
2. 从三级问题下拉列表中点击任意三级问题。

首次进入页面不需要调用，因为初始化接口已经返回默认 `selected_hazard`。

## 4.3 顶层字段

| 字段 | 类型 | 对应前端位置 | 作用 |
|---|---|---|---|
| `job_id` | `string` | 不直接展示 | 确认返回结果属于当前任务。 |
| `status` | `string` | 页面顶部状态提示条 | `done` 时更新详情；其他状态不更新现有详情，并显示处理中或错误提示。 |
| `selected_hazard` | `object/null` | 问题详情主体 | 当前选择的三级问题完整数据。 |
| `error` | `string` | 页面顶部错误提示条 | 任务失败时显示错误原因。 |

## 4.4 `selected_hazard` 字段

| 字段 | 类型 | 对应前端位置 | 作用 |
|---|---|---|---|
| `hazard_id` | `string` | 页面当前三级问题状态；三级问题列表选中样式 | 标识当前正在展示的三级问题。切换详情后，用于高亮对应选项。 |
| `category2_id` | `string` | 上方问题分类框和推荐标签选中状态 | 将当前三级问题与所属二级分类关联。选择三级问题后，上方分类和推荐标签同步变化。 |
| `category2` | `string` | 上方“问题分类”框 | 当前三级问题所属的二级分类显示名称。 |
| `issue_id` | `string` | 三级问题列表副标题；后续上报数据 | 《问题分级》中的正式三级问题编号。当前详情卡不单独显示，但上报时应携带。 |
| `category3` | `string` | 三级问题选择列表；切换成功提示 | 当前三级问题名称。可用于详情副标题或上报确认。 |
| `point` | `string` | 当前测试页暂未独立展示 | 当前问题在图片中的可见位置或对象。建议后续在“问题描述”上方增加“问题部位”一行。 |
| `description` | `string` | “问题描述”文本框 | 只显示当前三级问题自己的现场描述。切换问题时必须整体替换。 |
| `confidence` | `number/null` | 当前不直接展示 | 当前三级问题的原始置信度，范围 `0～1`。 |
| `confidence_percent` | `number/null` | 三级问题候选或详情置信度 | 百分比形式的置信度。当前主要在三级问题选择列表中显示。 |
| `rectification_advice` | `string` | “整改建议”文本框 | 只显示当前三级问题自己的整改建议，不得与其他三级问题合并。 |
| `regulations` | `array` | “关联条文法规”列表及“添加”弹窗 | 当前三级问题自己的全部法规。不得读取或合并其他三级问题的法规。 |
| `default_regulation_ids` | `array<string>` | 法规区域初始可见状态 | 默认展示的法规 ID，最多前三条。每次切换三级问题时，前端重新用该数组初始化可见法规。 |
| `remaining_regulation_ids` | `array<string>` | “添加”弹窗候选法规 | 除默认前三条之外的剩余法规 ID。当前测试页也会通过“全部法规减去已显示法规”动态计算。 |

### 切换三级问题后的页面更新规则

收到新的 `selected_hazard` 后，前端必须同时执行：

1. 更新当前 `hazard_id`。
2. 更新上方问题分类框为 `category2`。
3. 更新推荐分类选中状态为 `category2_id`。
4. 将问题描述整体替换为 `description`。
5. 将整改建议整体替换为 `rectification_advice`。
6. 清空上一三级问题的法规页面状态。
7. 使用新的 `default_regulation_ids` 初始化法规列表。
8. “添加”弹窗只读取新的 `regulations`。

# 5. `regulations[]` 字段说明

| 字段 | 类型 | 对应前端位置 | 作用 |
|---|---|---|---|
| `regulation_id` | `string` | 法规卡片内部 ID、可见法规集合、“添加”按钮 | 当前三级问题内的临时法规 ID，例如 `reg-1`。不写入 MongoDB。 |
| `standard` | `string` | 当前不单独展示 | 规范名称或规范编号。前端通常直接显示组合后的 `title`。 |
| `clause` | `string` | 当前不单独展示 | 条款号。前端通常直接显示组合后的 `title`。 |
| `title` | `string` | 蓝色法规卡片标题；添加弹窗标题 | 已组合好的“规范 + 条款”文本，例如 `GB 51309-2018 第3.3.2条`。 |
| `content` | `string` | 点击法规卡片后的展开内容；添加弹窗摘要 | 规范知识库精确匹配的条文原文。为空时前端显示“暂未返回已核验原文”。 |
| `verification_status` | `string` | 当前测试页未直接展示 | 条文原文核验状态，例如“已核对原文”或“待专业核对”。后续可显示为状态标签。 |
| `source` | `string` | 当前测试页未直接展示 | 条款来源，例如问题分级表、案例知识库或规范知识库。主要用于追溯和专业复核。 |
| `relevance_rank` | `integer` | 当前不单独展示 | 当前三级问题内部的法规排序。数值越小越靠前；前三条默认展示。该值是当前条款顺序，不是跨问题排名。 |
| `default_visible` | `boolean` | 法规初始显示判断 | 表示该法规是否属于默认前三条。当前前端主要使用 `default_regulation_ids` 初始化，也可用此字段校验。 |

## 5.1 默认展示规则

- 法规数量为 0：显示“当前问题暂无关联法规”。
- 法规数量为 1～3：全部默认显示，不显示“添加”按钮。
- 法规数量大于 3：只显示前三条，并显示“添加”按钮。
- 默认法规顺序不得由前端重新按规范名称排序。
- 前端应保持接口返回顺序或按 `relevance_rank` 升序。

## 5.2 “添加”按钮规则

1. 点击“添加”后，弹窗列出当前三级问题尚未显示的法规。
2. 用户选择法规后，将对应 `regulation_id` 加入前端 `visibleRegulationIds`。
3. 新增法规显示在当前页面。
4. 不调用 MongoDB 写接口。
5. 不修改接口原始数据。
6. 切换三级问题后，清空上一问题的添加状态。

# 6. 前端页面状态建议

测试前端目前使用以下核心状态：

| 前端状态 | 来源 | 作用 |
|---|---|---|
| `jobId` | 接口配置或 URL 参数 | 请求初始化和三级问题详情接口 |
| `view` | 初始化接口的 `mobile_view` | 保存分类推荐和三级问题候选 |
| `selectedCategoryId` | `default_category2_id` 或用户点击结果 | 控制问题分类框和推荐标签选中状态 |
| `selectedHazard` | 初始化接口或详情接口 | 控制描述、法规和整改建议 |
| `visibleRegulationIds` | `default_regulation_ids` + 用户添加 | 控制当前页面显示哪些法规 |
| `userAddedRegulationIds` | 用户点击“添加”产生 | 控制哪些法规可以在当前页面移除 |
| `imageUrl` | 初始化接口的 `image_url` | 显示现场图片 |

# 7. 状态与异常处理

## 7.1 初始化接口

| `status` | 前端处理 |
|---|---|
| `done` | 正常渲染 `mobile_view` |
| `processing` | 显示“处理中”，`mobile_view` 通常为 `null`，可以继续轮询 |
| `error` | 显示 `error`，停止刷新详情 |
| `not_found` | 提示 job_id 不存在 |

## 7.2 详情接口

| 情况 | 前端处理 |
|---|---|
| 返回 `done` 和 `selected_hazard` | 替换当前三级问题详情 |
| 返回 `processing` | 保留原页面，提示任务仍在处理中 |
| 返回 `error` | 保留原页面，展示错误提示 |
| HTTP 404 | 提示三级问题不存在，通常说明 `hazard_id` 已失效或任务结果发生变化 |
| 网络错误 | 保留当前详情，允许用户重试 |

# 8. 完整交互流程

```text
进入问题详情页面
  ↓
请求 GET /mobile-view
  ↓
使用 default_category2_id 显示默认问题分类
  ↓
使用 selected_hazard 显示默认三级问题详情
  ↓
用户点击其他 AI 推荐问题分类
  ↓
读取该分类的 default_hazard_id
  ↓
请求 GET /mobile-view/hazards/{hazard_id}
  ↓
替换问题描述、法规和整改建议
  ↓
用户点击“添加”法规
  ↓
只更新 visibleRegulationIds，不写入数据库
```

## 9. 前后端边界

以下字段是移动接口临时生成的展示字段，不进入 MongoDB：

```text
category2_id
hazard_id
confidence_percent
regulation_id
relevance_rank
default_visible
default_category2_id
default_hazard_id
default_regulation_ids
remaining_regulation_ids
field_labels
```

MongoDB 中仍然保存标准化 `result.hazards`，移动接口只负责把它转换为适合页面使用的结构。
